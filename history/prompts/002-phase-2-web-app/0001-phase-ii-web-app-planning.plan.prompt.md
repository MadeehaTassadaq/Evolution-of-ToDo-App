## Prompt

/sp.plan # SP Plan — Phase II: Full-Stack Web Application

## Phase Objective
Transform the Phase I in-memory Python console Todo app into a **production-grade, multi-user full-stack web application** with persistent storage and authentication.

This phase introduces:
- Web UI
- RESTful backend
- Database persistence
- JWT-based authentication via Better Auth

---

## Development Constraints
- All implementation must be generated by Claude Code
- No manual coding or direct file edits
- Every change must be spec-referenced
- Specs must be refined until correct output is generated

---

## Scope of Phase II

### Included
- Task CRUD (Create, Read, Update, Delete)
- Task completion toggle
- User authentication (signup/signin)
- JWT-secured REST API
- Persistent storage using Neon PostgreSQL
- Responsive frontend UI

### Explicitly Excluded
- Chatbot or AI functionality
- Kubernetes or Docker deployment
- Notifications or reminders
- Admin roles or RBAC
- Mobile applications

---

## Architecture Plan

### Frontend
- Next.js 16+ (App Router)
- TypeScript
- Tailwind CSS
- Better Auth for authentication
- JWT attached to every API request

### Backend
- FastAPI (Python)
- SQLModel ORM
- JWT verification middleware
- User-scoped API routes

### Database
- Neon Serverless PostgreSQL
- Tasks stored with user ownership
- Users managed by Better Auth

---

## Authentication Strategy

- Better Auth runs on frontend
- JWT tokens issued on login
- JWT included in `Authorization: Bearer <token>` header
- FastAPI verifies JWT using shared secret
- User ID extracted from token
- All queries filtered by authenticated user
