# Implementation Plan: Phase I Console Todo Application

**Branch**: `001-phase-1-console-todo` | **Date**: 2026-01-03 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-phase-1-console-todo/spec.md`

## Summary

Build an in-memory Python console application that enables users to manage todo tasks with three feature tiers: Basic (CRUD operations), Intermediate (priorities, tags, search, filter, sort), and Advanced (due dates, recurring tasks). The system will use clean separation of concerns (models, services, CLI) with no external dependencies beyond Python standard library, ensuring full spec-driven generation via Claude Code.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: Python standard library only (no external packages)
**Storage**: In-memory (Python dict/list structures)
**Testing**: pytest (optional - not required by spec)
**Target Platform**: Cross-platform (Linux, macOS, Windows) console/terminal
**Project Type**: single (console application)
**Performance Goals**: <1s for operations on 100 tasks, <500ms for search queries
**Constraints**: <100MB memory for 1000 tasks, deterministic behavior, serializable state
**Scale/Scope**: 1000 tasks max per session, single-user, no concurrency

### Source Code (repository root)

```text
src/
├── models/
│   ├── __init__.py
│   ├── task.py              # Task entity with all attributes
│   ├── recurrence_rule.py   # Recurrence pattern logic
│   └── task_list.py         # In-memory task collection
│
├── services/
│   ├── __init__.py
│   ├── task_service.py      # Business logic (CRUD, validation)
│   ├── search_service.py    # Search and filter operations
│   └── recurrence_service.py # Recurring task logic
│
├── cli/
│   ├── __init__.py
│   ├── parser.py            # Command line input parsing
│   ├── renderer.py          # Output formatting and display
│   └── commands.py          # Command handlers (add, delete, list, etc.)
│
├── lib/
│   ├── __init__.py
│   ├── validators.py        # Input validation (dates, priorities, etc.)
│   └── utils.py             # Utilities (ID generation, date parsing)
│
└── main.py                  # Entry point - REPL loop

tests/                        # Optional (not required by spec)
├── test_models.py
├── test_services.py
└── test_cli.py
```

**Structure Decision**: Single project structure selected because this is a standalone console application with no frontend/backend separation or mobile components. All code resides under `src/` with clear separation: models (data), services (logic), CLI (interface), and lib (utilities).
